# Critical Business Logic Review — 2026-08-12.3

Reviewed: 2026-08-12

Scope: WireGuard restart/apply behavior, routing-table allocation, multi-address and dual-stack policy routing, and BGP peer reconciliation.

## Findings

### P1 — WireGuard restart loses configured-path and source-of-truth semantics

`RestartWGConfig` brings down the literal interface name `wg0`, which makes `wg-quick` search its standard configuration directory instead of using the configured `-wg-config` path. With a custom directory, teardown fails silently and the subsequent `wg-quick up <custom-path>` fails because `wg0` still exists.

With `SaveConfig=true`, teardown can also overwrite the freshly rendered YAML-derived file with the old live state immediately before startup, undoing the configuration the user asked to apply.

Status: **fixed**. Restart now probes for `wg0`, uses the configured file for teardown and startup, preserves the rendered source-of-truth file across `SaveConfig` teardown, and propagates real teardown failures. Command-level tests cover running, missing, failed teardown, and file-overwrite paths.

### P1 — A newly created dual-role peer receives one routing table for two roles

Peer creation assigns the exit-node and policy-routing table IDs from the same unchanged peer slice. Because the new peer is not reserved between calls, both allocations return the same table ID. Exit-node routes and the peer's own policy routes then share state and can route traffic back through the peer itself.

Status: **fixed**. Creation reserves the exit-node allocation before requesting the policy table. Full-config validation rejects missing and duplicate table IDs across both roles.

### P1 — Strict and exit-node routing covers only the first configured peer address

Policy-rule generation reduces comma-separated `AllowedIPs` to `FirstIP`. Secondary IPv4 or IPv6 addresses receive no exit-node lookup, policy-table lookup, or strict reject, allowing traffic to fall through to the main table. Exit-node route generation likewise builds only one address-family path.

Status: **fixed**. Routing emits rules for every configured address or authorized source prefix and uses explicit IPv6 rule commands. Full exit nodes install both IPv4 and IPv6 defaults; split and policy routes select their address family from the destination CIDR.

### P1 — Every successful configuration save restarts all BGP sessions

The desired BGP peer contains a freshly allocated `LocalAddress` pointer. `bio-rd` deduplicates the stored pointer and its `NeedsRestart` method compares pointer identity, so an otherwise identical desired peer always appears changed. Every eligible `Store.Write` therefore disposes and recreates all BGP peers, temporarily withdrawing learned routes.

Status: **fixed**. Desired BGP addresses are canonicalized before comparison. Unchanged peers remain established, while semantic changes—including filters—replace only the affected peer so future passive sessions inherit the new configuration.

## Implementation Plan

1. Correct `RestartWGConfig` to inspect `wg0`, preserve the rendered file, tear down through the configured path, restore the desired file, and propagate real teardown failures.
2. Reserve distinct table IDs during peer creation and reject missing or duplicate active table IDs at full-config validation.
3. Expand peer source rules across every configured address; make generated rule and exit-route commands explicit about IPv4 versus IPv6.
4. Canonicalize BGP local addresses and compare route-filter chains semantically so unrelated saves preserve established sessions.
5. Add focused regression coverage, then run the race-enabled suite, `go vet`, Linux amd64/arm64 builds, and `git diff --check`.
